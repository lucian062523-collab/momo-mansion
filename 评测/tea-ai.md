## 2. 每日计划（只给模型看）

每次白天先调用一次，返回严格 JSON：

```json
{
  "wolf_chat": {"hammer":"千春","deep":"茶终","charge":"小野","knife":"池田","push":"池田"},
  "plans": {
    "千春": {"claim":"悍跳预","stance":"不信池田","suspect":["池田","他先点我"],
             "voteIntent":"池田","reason":"他先点我","responseTo":""},
    "池田": {"claim":"民","stance":"不信千春","suspect":["千春","她先扣帽子"],
             "voteIntent":"千春","reason":"她先扣帽子","responseTo":"千春"}
  }
}
```

- 狼队先私聊：悍跳/倒钩/冲锋/今晚刀谁/今天推谁；计划 prompt 明确要求 **reason 只能是公开依据**，私聊/刀人计划不得进入公开理由（代码二次清洗）。
- 预言家按验人结果决定起跳/藏；女巫/猎人按人设决定藏/拍身份。
- 计划只写进 `state().plans/wolfChat` 供验收，不进玩家 UI。
- AI 计划解析失败/断网 → `fallbackPlans()`：按身份、上一轮票型、热度、保护关系生成一套仍然自洽的计划，保证狼队私聊/票意图存在。

## 3. 公开发言（beat 驱动 + 硬校验）

每个 NPC 的 beat 由计划生成：

| 字段 | 来源 |
|---|---|
| `who` | 座次顺序，每人一句 |
| `respond` | 上一句点名/怀疑我的人；没有就上一位发言者 |
| `target / voteIntent` | 计划 voteIntent（合法化；狼不投狼） |
| `claim` | 计划 claim（民/预/女/猎/悍跳预/倒钩狼/冲锋狼/深水狼） |
| `stance` | 计划 stance（信谁/不信谁） |
| `facts[]` | 计划 reason + 昨夜公开离席/带人/上一轮被放逐/谁投了你；跨 beat 去重，避免同一句事实复读 |
| `lens` | 角色性格镜头（见 §4） |

Prompt 硬要求：第 1 句先回应 `respond`；点名 `target`；说出 `facts`；明确站边+今天票意向；1~3 句、第一人称、口语；自然体现 lens；禁止编号/座位号、旁白、总结、全知、AI 套话、灵异化、复读、复用 6 字以上连续短语。

校验不通过 → 该组重试一次（`retry` 提示具体不合格项）→ 仍缺用 `fallbackBeatLine()`（同样带 respond/target/fact/票意图/性格镜头）。

## 4. 性格镜头（已人化）

| 角色 | lens（已写入配置/prompt） |
|---|---|
| 千春 | 高智商冰娇：清冷、聪明、体面，情绪收得很稳；占有欲/控制欲只在细节里漏，不把池田挂嘴上、不每句咬人；软萌是伪装 |
| 池田 | 冲动、易怒、怕千春；想回到父母健在的从前；被逼急会语无伦次，常用预设前提的指责。**删除杯子/座位/被害妄想** |
| 茶终 | 老茶师/大家长/惜字如金；看手上的小动作、茶盏的摆法、火候；短、下结论、不解释；护樱井。**禁止听水/水声/听停顿；禁止固定梗** |
| 樱井 | 清冷、要强、背负家庭包袱；先结论后理由、像会上陈述；被质疑先解释动机（越解释越像掩饰）再冷压回去；绝不当众示弱。**不是记录仪，不说记下/编号/第几位/时间线** |
| 小野 | 对女儿要求很高的母亲：好胜、强硬、理性冷漠，把不甘压到幸子身上；要求高、会当众挑幸子的错、不轻易夸；护是“我的女儿只能我管”，不是温柔挡刀 |
| 幸子 | 怯、精确，怕让母亲失望；发现漏洞也不敢坚定带队；想被需要；和母亲小野的关系要能看出来 |
| 墨墨 | 毒舌、观察准、护玩家但嘴硬；句子短，先给判断，再补一句理由；**不用“挡话”固定句** |

校验层对每句做 `LENS_RE` 命中检查（AI 不合格则重试/兜底），保证性格不是只换声线。

## 5. 票意图一致 + 玩家输入

- `normalizeVotes(g, raw, plans)`：每个 NPC 的票优先用本轮 `plan.voteIntent`，非法才用权重兜底；`g.plannedVotes` 与 `g.npcVotes` 同时落状态。实测第一天实际票与公开 voteIntent **0 mismatch**。
- 玩家输入解析：`我信X / 我相信X / 我站X / 我点Y / 我怀疑Y / 我投Z / 票给Z` → `g.playerStance`；下一次计划 prompt 带上，要求至少一位 NPC 的 `responseTo` 回应玩家/该对象；buildDayBeats 会强制一个 beat 回应玩家并写明“玩家上轮公开信你/点名你”，随后清空，避免重复消费。
- 玩家提示：输入框 placeholder「可写：我信谁 / 我点谁 / 我投谁 / 理由」，不新增布局。

## 8. 开源 AI 狼人杀参考（v5 prompt 已落地）

参考：[AgentWereWolf](https://github.com/yingyingxia666/AgentWereWolf) / [AGENT_ARCHITECTURE.md](https://github.com/yingyingxia666/AgentWereWolf/blob/main/AGENT_ARCHITECTURE.md)、[AI_wolfgame](https://github.com/Xiaopacai369/AI_wolfgame)、[ai-werewolf-vn](https://github.com/fantay0312/ai-werewolf-vn)、[monad AI-Werewolf](https://github.com/monad-developers/AI-Werewolf)。

1. **法官/引擎与 agent 分离**：状态/身份/存活/轮次由程序维护，LLM 只做角色决策 → 本项目计划+导演 beats+引擎票/刀/验/药。
2. **公开/私有记忆分层**：每个 agent 只有自己的私密信息+公开事件流 → prompt 分 `【私密记忆】`/`【公开记忆】`。
3. **发言前先计划**：先定意图再生成台词 → 每日 `plans`（claim/stance/suspect/voteIntent/reason/responseTo）+ 狼队私聊。
4. **投票/发言前反思**：回看谁投我/谁替我说话/谁带节奏 → facts 带上一轮票型/被点，回应对象强制。
5. **反全知/反幻觉 + 结构化校验**：不能借“允许说谎”合理化幻觉 → 校验层拒绝虚构死亡/缺席/主持、编号、AI 套话、复读。

## 9. 剩余风险

1. **接口稳定性**：pages.dev 随机 1.5~15s/挂住；已 6.5s 首字重连+15s 超时+计划/发言兜底。
2. **计划 JSON 依从性**：计划解析失败会走 `fallbackPlans`（自洽但台词个性弱）；可调 `plan_max_tokens` 或提示词。
3. **调用预算**：计划 1 次/天 + 发言 1~2 次/天 + 结局 1 + 玩家接话 ≤2，硬上限 15；长局后半段可能用兜底保预算。
4. **性格镜头**：AI 偶尔仍写套话/标签，校验会重试或兜底；`LENS_RE` 是硬门槛，可能牺牲少量台词自然度。
5. **玩家站边只验证到“写入并进入下轮计划/强制回应”**；完整多轮说服链路未单独跑长局。
6. 手机仅 headless 844×390 验证；真机软键盘/安全区仍需过一眼。
7. `state()/debug` 暴露 plans/wolfChat/roles 供验收，发布前可脱敏。
