## 2. 续写思路

1. **不重复 1/5 最后一句**，直接从「她说完」之后的空间检查写起：数杯子 → 摸茶温 → 从桌布褶里拈出一角烧焦的火漆。三个小物把「梦」与「真」缝在一起，也让读者先于墨墨一步意识到「这桌茶有人刚摆好」。
2. **墨墨承担推理与毒舌，你只负责看和问**。她的害怕不写成台词，写成身体：膝盖在抖、手背凉得不像活人、坐下时肩与肩只剩一道缝。她越怕越凶，凶完再补一句软话——这是 1/5 的语法。
3. **七客一人一个执念**（全部从 `party_月见茶会.json` 的对局行为反推，见 §5）：千春占位、池田护杯、茶终听水、樱井编号、小野护幸子、幸子记账、月见主持。没有一句「为机制服务的假线索」。
4. **规则只写月见该说的部分**：八席三狐、找出或别被找到、照镜/药茶/末茶三样东西、白日举盏、赢方许愿；对局细节一律交给引擎，入席收在「闭眼」。
5. **三结局共用同一骨架**：月见说破「她的愿望不在茶里，在桥上」→ 千春走时的一问 → 墨墨的题眼 → 鸟居点灯。差异放在月见的揭示语、墨墨的反应、灯下最后两三句：A 是揭面，B 是让愿，C 是替空位说完。
6. 文风约束：第二人称、现在时、短段、感官细节；比喻克制（瓷偶、釉、海漩涡、贴身的罩子），不堆形容词；墨墨台词不搬 1/5 原句、不复读旧稿口癖。

## 3. 引擎兼容性核对

- 节点类型只用 `director.js` 已接的：`narration / say / expr / scene / sprite / cg / cgoff / stage / choice / set / lamp / end`。无 `vo` 字段，无新节点。
- `say.who` 只出现 `player` 与 party 里的 NPC 名（月见/千春/池田/茶终/樱井/小野/幸子）；墨墨的台词缺省 `who`。
- NPC 表情全部落在 `party_月见茶会.json` 的 `chars.*.exprs` 里（含月见的「疑惑」、池田的「欲言又止」、幸子的「低头落寞」等）。
- `stage` 只用于 7 位 NPC 出场（入席 7 个），退场交给幕三 `party.finish` 的清台；落座点位由 `party_月见茶会.json` 的 `stage_slots` 决定，不在剧本里写死。
- `choice` 两个选项都落 `set {path:"bridge.wish", value:"happy"|"far"}`，选项 `say` 由引擎按玩家话播出。
- `scene` 的 `period` 只写「夜晚」「夜晚开灯」；正文开场 `卧室` 用小岛别名（map.json 卧室→卧房），与《前言》写法一致。
- CG 用实际存在的原文件名：`墨墨偷偷拆信.png`、`玄关信封特写镜头.png`、`茶室空镜兼背景.png`（均在 `墨墨-美术资产-web/CG插画包/月见前言/`）。
- 结局顺序：先 `scene 鸟居` 再 `lamp`——点灯光效必须落在鸟居场景上；`then:"party:finish"` 在 script 级，灯量落档由 party.js 统一写，回放不重写。若校验非要「lamp 后接 scene」的字面顺序，可把两者对调，但会丢点灯背景。

## 4. 需要作者拍板/确认的句子

1. **墨墨说漏的「主人」**：长桌边她压低声音说「别让主人看见」，说完自己愣了一下。这是故意埋的钩（她明明说「从没来过」）——留还是删？
2. **茶温**：「茶是热的」「没墙没门的地方，茶却是热的。你品品。」把茶温写成「有人刚摆好」的线索。要不要更冷一点（比如「温得像有人刚走」）？
3. **千春的愿望**：「我要池田哥哥明年、后年、每一年，都坐在我旁边。」——现在偏「宣言」，要不要更病娇（「不坐过来，我就把杯子收走哦」）？
4. **池田的愿望**：「我要回到从前。父母都还在。……千春没有见过我。」——按设计稿原文的意思写成短句，语气够不够碎？
5. **樱井问名字**（散文有、节点草案删去）：樱井「这位怎么称呼？」—墨墨「墨墨。」—「……好。我记下了。」要不要补进 `ch1_入席`（+2 节点）？
6. **题眼两拍**：「我想要的，从来不是把谁留在身边。」「是和他一起，走出去。」现在分成两句。新文风下要不要改成一句一气说完（更狠），还是保持停顿（更像她）？
7. **月见的揭示**：「她的愿望不在茶里。」「在桥上。」——拆成三句是否太直白？要不要只留「在桥上」。
8. **C 线空杯**：她把你的空杯挪到手边、杯口朝里「像护着什么」，最后「这句，我替他说」——这个意象留不留。
9. **玩家愿望**：按任务只做 happy / far 两个选项并落 `bridge.wish`；设计稿原有的第三个「……说不出口」（旧字段 `story.wish = secret`）要不要补回、落哪个字段？
10. **点灯特写**：现在只有 `lamp` 光效 + 鸟居场景，没有点灯特写图（设计稿 §8 缺口）。若要做，建议仍用 `月见特写.png` 或 `茶会番外CG.png` 过渡，需美术拍板。

## 7. 1/5 与对局数据的冲突（以 1/5 为准的处理）

1. **空间**：1/5 说「只有长桌、没有墙和门」，引擎幕二用「茶歇间」房名与桌视图叠层。处理：叙事保留无墙无门，`ch1_入席` 的 `scene` 仍写 `茶歇间 / F3`（桌视图是叠层，不依赖房间美术）；第一眼用 CG `茶室空镜兼背景.png` 撑「长桌浮在光里」。**建议作者给这个空间一个自己的房间名并补一张场景图**，否则玩家会记得「茶歇间有墙有门」。
2. **请柬**：1/5 的飞散物里有「一枚熟悉的、边缘烧焦的请帖」，但《前言》的道具 CG `请柬（道具）.png` 边缘完好、火漆完整。处理：按 1/5 为准，写成梦里的请柬被烧焦，并在入席用「桌布褶里的火漆碎片」接住。若要保「请柬完好」，可把碎片换成茶渍/焦痕。
3. **房间名**：1/5 写「卧室」，`scenes.json`/`map.json` 里是「卧房」（map.json 有别名 卧室→卧房）。节点沿用「卧室」，与前言的写法一致，`scene.js` 会自动走别名。
4. **CG 文件名**：任务清单写 `玄关信封.png`，仓库里实际只有 `玄关信封特写镜头.png`（前言用的就是它）。节点用实际文件名；另 `茶室空镜兼背景.png` 与任务清单一致。
5. **愿望字段**：任务要求 `bridge.wish`（happy/far）；设计稿 §4 旧写 `story.wish`，还有第三选项 `secret`。本稿按任务只用两个选项、落 `bridge.wish`。`party.js` 目前不读这个字段，幕三只在剧本里按分支走。
6. **1/5 原稿粘贴痕迹**：最后两行是半角括号/半角省略号（`...(不悦)`、`...不应该`）。节点里保留 `...` 原文、表情走 `expr`；散文里统一为「……」。
7. **1/5「小岛上……」** 与《前言》「这座海岛」一致，无冲突。
