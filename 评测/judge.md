## 0. 结论先行

**这是一款"美术与内容量远超同类 jam、但第一眼与第一分钟保护得很差"的作品。** 制作规格（57 套立绘、23 张 CG、1777 个词、32 房间旁白、68 句语音、95 个音频、PSD 级 UI）在 21 天 game jam 里属于第一梯队；但它把最贵的东西（185 节点《前言》、8 灯主线）藏在一个需要「设置→返回标题→剧情通道→进入→从头回溯」五步才能到的地方，而第一分钟玩家看到的默认房间点「玩」是一句「小游戏还在做」，主题「字海」在常态下几乎不可见。如果按评审初筛的 30 秒/3 分钟体验给分，会明显低于它的实际家底。

**三条交付级红灯（建议 1 小时内处理）**

1. `墨墨上线包.zip` 是 18:55 的旧包：包内 index.html 没有 20:06 之后的「用自己的 Key」等修复（`grep momo.chat.key` 为 0），而 dist 已更新到 20:29。**必须重新构建 + 重新打包，并校验包内 index.html 与 dist 一致。**
2. 手机横屏"直接打开"时布局视口被 1920 舞台撑大（实测布局视口 1594/1750，可视区只有 844×390），舞台被渲染成 1438×809：名字弹窗的「确认」、主画面右侧「地/学/玩/说话」、小游戏右列全部出屏——**手机上等于玩不了**。已实测一段 3 行 CSS 可修复（见问题 2）。
3. 《前言》演完只演了「灯缓缓亮起」的动画，`bridge.lit` 仍是 0（实测 FINAL `{"lit":0,"prologue_done":true}`）：剧情通道永远「已点亮 0/8」，`MomoParty.replay()` 因 `ch1_done` 永不落定而不可用，8 灯元进度是死的。

## 2. 逐维评测

### 2.1 主题「涌现」契合度：6/10

**成立的部分（设定层）**
- 「她说的每个字、你教她的每个词，最后都落进同一片海」——把语言学习当燃料、把关系当副产物，是对「涌现」的一个聪明且可实现的解释。`wordsea.js` 的三形态（潮/瀑布/浪）设计完整：密度=词量、落速/摆幅=心情、色温=好感、物资<40 时字会碎（`game/js/wordsea.js:44-75`）。
- 学习与对话确实在喂这个系统：`momo:chatline` → `fall()`（`wordsea.js:333`）、新词入库 → 落一场（`wordsea.js:340-352`）。

**不成立的部分（呈现层，这也是评委打分的地方）**
- **常态下没有字海**：`AMBIENT = false`（`game/js/wordsea.js:31-33`），`P.dens` 恒为 0（同文件 68 行）。实测主画面 `MomoWordSea.state()` 返回 `{running:false,parts:0,falls:0}`；截图 `/tmp/momo-judge/prologue/38-home-after-prologue.png`（干净的主画面，一个漂浮字都没有）。作者 2026-10-20 因"像灰尘"撤掉常驻词海，但这一撤同时撤掉了主题的唯一常驻证据。
- 字海只在两件事发生时出现：① AI 聊天回复（`momo:chatline`，但聊天依赖 `https://momo-chat-api.pages.dev/chat`，本机实测 `net::ERR_ABORTED`，无网即无）；② 学会一个新词时单字下落 3 秒。实测强制触发后的画面 `/tmp/momo-judge/prologue/39-wordsea-fall.png`：几枚散字（学/她/这/片/个/在/里/的），读起来像"飘字特效"，不像"海"，更不像"涌现"。
- 标题页四卡「新的故事 / 继续旅程 / CG鉴赏 / 剧情通道」没有任何一处提示"语言/字/学习/涌现"；名字弹窗盖在上面。**评委 30 秒内的信息是：一个很漂亮的二次元 AVG。** 截图：`/tmp/momo-audit/00-title.png`、`/tmp/momo-flow/01-boot.png`（竖屏转横提示）。
- 主题在"文本层"的落点是有的，但要看到 185 节点的《前言》才会有（信/八灯/语言），而它藏在标题菜单深处。

**可执行改进**
1. 恢复一版克制的常驻字海：`AMBIENT = true`，但 `P.dens` 改为 `40 + min(80, n*1.2)`、`alpha` 从 0.26 降到 0.10-0.14、只在下 2/3 屏与左右两侧生成（`spawn()` 已避开中间脸，`wordsea.js:144-146`）。工作量 0.5-1 h；**需作者拍板**（他明确说过不要"灰尘感"）。
2. 主画面加一行小字读数的"词海 N 词"（挂在 timebar 下），让"越学越满"有可读证据；学词时的 `fall()` 保留。
3. 开场 38 节点里插 1 个 3 秒演示：她说一句话 → 那句话的字从屏幕顶落下来 → 字幕 `这些字，是你教我的。`（文案需作者拍板）。工作量 0.5 h。
4. 标题页副标题一行，直接给评委看题眼（例：「她说的每个字，都是你教她的」）。工作量 10 min，需作者拍板。

**四要素判定**
- **目标**：缺。首小时内玩家唯一能自己拼出来的目标是"赚钱/好看/好感"，而真正的主线目标（点亮第一盏灯、看茶会）既没被提示也进不去（见 2.4）。直接后果：首小时留存点只能靠"再背几个词/再买一套衣服"，撑不住 30 分钟。
- **规则**：有，但全靠玩家自己摸。物资 12/天、准确率 ≥90% 有日结奖励、小游戏每日 3 地点、送礼好感公式，全部没有教学；`dialogues.json` 的开场只说了"我负责你的语言学习"。玩家在第一次跨日结算前根本不知道物资会掉。
- **挑战**：合格。SRS 复习、四选一、五种小游戏内核（打水漂/出餐/连线/语序/寻物）、每日配额都在；风险是难度曲线没被验证（首日 4 选题给的是 IELTS 7.5+ 词库，见截图里的 epidemic）。
- **反馈**：本作最强项。toast、Q 版陪读表情（`qmomo.json` 11 张按对错挑脸）、金额跳动、好感星级、日结算账单、换装/送礼回话——正反馈密度高，且几乎都是正向不惩罚。
- **首小时留存点**：学习侧的"+5 货币"和服装/CG 收集能撑 10-20 分钟；20 分钟后再无新东西可看（剧情进不去、小游戏一半房间空、地图没名字）。**建议把"第一天晚上收到请柬"做成硬钩子**（见 2.4）。

### 2.4 叙事与演出：8/10

**做得好**
- 《前言》185 节点（`game/content/dialogues.json` /脚本/ch1_前言，`nodes` 0-184）：第一人称、电影化分镜、CG 3 张（玄关外套特写 / 码头望桥 / 月见特写）、章节 flag `bridge.prologue_done`。
- 演出系统真的在跑：`cg` 全屏/`prop` 弹出式道具、`sprite` 强制显隐、`map_hint` 高亮码头并切楼层、`await_room` 等玩家走到码头、`daze` 走神背词（真词卡 10 张，前 5 张手动翻，第 6 张起模糊摇晃自动翻——截图 `/tmp/momo-judge/prologue/24-stuck-211.png` 是走神卡第 1 张 negotiate）。
- 语音：53 句 say 中 38 句有 `vo`（vo-st-001..068，火山清冷女声），实测无播放报错（本评测静音，未主观听感）。
- 开场 38 节点写了第四面墙玩笑（"哎呀在上课摸鱼玩的啦"），对 jam 评委是讨喜的。

**问题**
1. **入口在迷宫尽头**：dist 里《前言》唯一入口是「设置 → 返回标题 → 剧情通道 → 第 1 盏 → 进入 → 从头回溯」。新玩家点「新的故事」直接落主画面，看不到任何剧情入口。（源码 20:49 已在主画面加了一个「剧」按钮 + 开场演完接 going 的补丁，但不在 dist，且需重建验证。）
2. **进度不落档**：预告"八盏灯"是主线，但《前言》结尾 `lamp` 只放光效不写 `bridge.lit`（`game/js/director.js:550-552` 调 `lampCeremony`；写档在 `party.js:781-783` 的 `finish()`，而 `finish()` 只由 `then:"party:finish"` 触发，《前言》没有 then）。实测 `{"lit":0,"prologue_done":true}`；`chapters.json` 的 `ch1_done` 也永不落定 → `MomoParty.replay()` 永远返回 false。**主线在玩家眼里结束于"0/8 灯、无法重看"。**
3. **收尾断头**：最后一张 CG 是「月见特写」（茶会主持人，章节已删，玩家不认识她），紧接着直接结束——没有"第一盏灯已亮"的 toast、没有"下一章在路上"的卡。实测结束瞬间画面会退回主画面（空房、无提示），截图 `/tmp/momo-judge/prologue/37-end.png`。
4. **文本瑕疵（都是首屏级）**：开场第一句 `你好...{{name}}。` 用三点、第二句 `认识你.....也就一般高兴吧。` 用五点、`来着..诶,对了` 混半角逗号（`dialogues.json` /脚本/开场/nodes[3][5][8][11]）；《前言》有 `她今天哪去儿了？`（nodes[16]）、`八盏灯的光熖`（nodes[30]，应为"焰"）。玩家第一分钟就能看到前三处。

### #1 主题在 30 秒内不可见（字海常态关闭）【P0】

  2. 主画面 timebar 下加「词海 N」小读数（找 `## 主画面` 的 timebar HTML 或 `name.js refresh()` 同款注入）。

  4. 标题页加一句副标题。
- **工作量**：代码 0.5-1 h；文案 10 min（需作者拍板，因为他明确要求撤过常驻字海——建议用"只在下半屏、极淡、密度随词量"折中，并让他看一眼截图再定）。

### #2 手机横屏"直接打开"布局崩（WebView/TapPlay 高危）【P0】

- **证据**：`/tmp/momo-flow2/verify-raw.png`（名字弹窗右半和确认按钮出屏）、`/tmp/momo-flow2/07-main-after-intro.png`（主画面缺右侧三键）、`/tmp/momo-flow2/14-play-study.png`（小游戏右列释义出屏，**无法完成配对**）；`innerWidth 1594/1750 vs clientWidth 844`。
- **根因**：首帧 `.stage` 是 1920×1080，超出 844 视口 → Chromium mobile 把布局视口撑到内容宽 → `fitStage()`（`UI还原/js/ui.js:14`）按被撑大的 `innerWidth` 计算 scale，舞台实际渲染 1438×809；同时 `@media (max-width:900px)`（`UI还原/css/common.css:1136`，手机放大按钮/重排）失效。
- **修法（已实测有效）**：在 `UI还原/css/common.css` 顶部（`#screens` 规则附近，第 39 行）加：
  ```css
  html, body { width: 100%; height: 100%; overflow: hidden; }
  #screens { position: fixed; inset: 0; overflow: hidden; }
  ```
  注入后 `innerWidth=844`、舞台 `693×390` 居中、弹窗完整（`/tmp/momo-flow2/verify-clamp.png`）。
  可选加固：`ui.js:14` 改用 `document.documentElement.clientWidth/clientHeight`。
- **验证**：重建后 844×390 手机模式截图对比；真机 Android Chrome / TapTap TapPlay 各开一次（重点：**直接横屏启动**与先竖后转两条路径）。
- **工作量**：0.5 h + 真机 0.5 h。

### #4 聊天联网 vs「单机、不得提供联网服务」规则冲突【P0 合规】
