## 0. 一句话结论

**人设与接话质量已经能用，但三个硬伤必须今晚修：① prompt 里的「接话范例/语感参考」仍被逐字照抄（特定触发句实测 100% 撞示例）；② 断网/失败 3 次后聊天永久锁死在台词池，网络恢复也不恢复；③ AI 对话是联网服务，与 jam「不能提供联网服务」规则正面冲突，需要作者拍板投稿形态。** 另外线上实际跑的模型是 `deepseek-chat` 而不是记忆里调过的 `deepseek-flash`（`GET /chat` 自报），延迟因此更快、但照抄更严重。

### 2.4 7 秒首字重发 / 15 秒兜底（浏览器实测）

- 用本地假代理（`http://127.0.0.1:8791/chat`，通过 `window.MOMO_CHAT_URL` 注入，不改任何游戏文件）复现：第 1 条 POST **挂 9 秒不响应**，第 2 条立即流式返回。
  - 实测：第 1 条 POST 在 +6ms，**第 2 条在 +7010ms 发出**，气泡在 **+7055ms** 显示「第二条连接。……接上了。」，`failed=0`、`busy=false` —— **7 秒首字重发 → 重发成功的完整链路是通的**，这个策略合理，建议保留。
  - 另一次 puppeteer 直接拦截的对照实验里，第 2 条 mock 响应的时序没被正确解析，最终回了兜底台词 —— 属测试桩问题，不代表产品路径。
- 但代码里 `TIMEOUT = 15000` 只作用于「重发那次的首字」，第 1 次请求的硬超时是 `25000`；最坏路径 **7s 重发 + 25s 硬超时 = 32s**，与注释「15 秒整体兜底」不符（P2）。
- 代价：每次挂住 = 2 条请求（作者被计费 2 次、代理 20/分 限流也被吃 2 次）。在 8 次代理采样中 0 次触发 7s 重发（max 4101ms），当前触发率不高，**可以保留**。

## 5. 表情映射（exprFor）回归

从 `game/js/chat.js` 源码抽取 `exprFor()` 原函数（不是复制版）跑 23 条回归用例：**22/23 通过**。

**唯一真失败（低危，属规则顺序冲突）**：
```
exprFor('那就早点睡。……我又没催你，是你自己说要做完的。', '')
  → 害羞    期望（记忆里的回归项）：眯眼笑
原因：「害羞」词表里的「我又没」在「眯眼笑」之前命中，把「早点睡」的暖意抢走了。
影响：这两张脸都偏暖，观感损失小；但说明「记忆里记录的 14+9 条全过」对完整句子并不成立。
```
（另有一条「赶紧睡吧！」我最初期望默认，实际眯眼笑——这是对的，不算失败：记忆原文只要求它别被判成惊讶。）

**更大的问题是分布与错配（按 29 轮真实回复统计）**：
1. **害羞 0 次**：害羞要命中「别多想/才不/谁要/自作多情/碰巧/顺路/我是说/我又没」，而她的回复几乎总是先「……」 → 被 `…… → 欲言又止` 截胡。**被夸、被示好、被表白这三类最该害羞的场合全部显示欲言又止**（s03/s04）。
2. **眯眼笑 0 次**：要求回复里出现「歇着/早点睡/去睡/别硬撑/吃饭/饿了…」，模型很少正好用这些词；而 s16「临睡」那条反而因为「你倒是」判成不悦。
3. **分手/重话 → 默认**（s05）：`heavy` 只被用来「禁止笑」，没有给重话配一个表情，默认脸在分手语境里最违和。
4. **疑惑 8 次**里有一半是「反问句结尾」被当成困惑脸（如 s10「想挑我穿得不对？」其实是挑衅，不是困惑）。

**可直接落地的修法（P1，~40 行）**：
```js
// 1) 用玩家这句 + 她的回复联合判定「被夸/示好」→ 害羞（放在「……→欲言又止」之前）
var praise = /好看|漂亮|可爱|温柔|喜欢你|爱你|梦到|想你|一直.*住/.test(u);
if (praise && /……|才不|谁要|别多想|怪不|不自在|嘴甜|干嘛/.test(t)) return "害羞";
// 2) 重话必须有「不笑且不难看」的落点
if (heavy) return /……|再说|改天|没凉/.test(t) ? "欲言又止" : "低头落寞";
// 3) 反问结尾不再一律「疑惑」：挑衅/毒舌的语气词优先
if (/你倒是|想挑|找我有事|真要我走|心里没数|你当我是谁/.test(t)) return "不悦";
if (/[？?]$/.test(t)) return "疑惑";
```
另有低级修法：把「我又没」从「害羞」词表挪到「眯眼笑」之前先判定（或直接删掉「我又没」），让「早点睡」回归眯眼笑。

## 6. P0：「接话范例/语感参考」仍在被逐字照抄

### 6.1 证据（32 次专项采样，直连）

prompt 里现有 **11 行可抄示例**：语感参考 4 行 + 对话范例 3 行 + 接话范例 4 行，其中「正好，茶泡多了…」出现两次（语感参考第 1 条 = 对话范例第 1 条），等于给模型双重强提示。

| 触发词 | 采样 | 严格逐字（≥8 字连续） | 骨架复用（5~7 字） |
|---|---|---|---|
| 今天好累啊 | 8 | 2（25%） | 1 |
| 你在干嘛 | 8 | 0 | 2 |
| **我昨天梦到你了** | 8 | **4（50%）** | **4（50%，合计 100% 撞示例）** |
| 教我个单词 | 8 | 1（12.5%） | 0 |
| **合计** | 32 | **7（22%）** | **7（22%）** |

典型证据（原样）：
- 触发「我昨天梦到你了」→ `……梦到我什么。说清楚，不然别想睡。`（与接话范例几乎逐字一致；deepseek-chat 下 **2/2 次一字不差**）
- 触发「教我个单词」→ `serendipity。意思是「意外发现好东西的运气」。像遇到我这种。……记住了没。`（30 字连续重合，连选择的单词都一样）
- 触发「今天好累啊」→ `累就歇着。别硬撑着倒在门口，我还得拖你进来。`（接话范例原句，只删了「……我是说」）
- 主矩阵 s23-1 同一句逐字复现。
- **deepseek-chat（线上实际模型）比 flash 更爱照抄**：「我梦到你了」2/2 一字不差；「你在干嘛」直接输出接话范例原句「把晾在外面的书收进来，风大。你找我有事？」。
- **真实浏览器链路（Chrome + 本地 dist + 真实 pages.dev 代理）也在抄**：2 次提问里 1 次是对话范例的近逐字改写——「今天好累啊」→「累就早点睡。我又没催你，是你自己说累的。」（对照范例「那就早点睡。……我又没催你，是你自己说要做完的」）。

### 6.2 为什么必须改

1. 玩家一旦聊到示例覆盖的场景（累、在干嘛、梦到、教单词），就会撞见**同一句话**——多聊两轮立刻发现「她是复读机」，jam 评委的 AI 对话体验分直接崩。
2. CODELY 19:55 已经总结过「示例别写」，作者后来又把示例加回去了（20:16/20:27 的人物调性修订带入）。
3. 改法几乎没有成本：删示例 + 加禁句清单 + 一条后置过滤，不改变人设。

### 6.3 修改草案（P0，prompt 内，~20 分钟）

把 `systemPrompt()` 里 `lines` 数组从 `"语感参考…"` 到 `"接话范例…"` 这一整段三块（chat.js 第 195~210 行：语感参考 / 对话范例 / 接话范例）整体替换为：

```
语气怎么落地（只描述，不给可抄的句子）：
· 短句，两三个字一顿，没说完就用「……」，一轮最多两个「……」。
· 被夸/被示好：先顿一下，再挑他一个毛病或者用别的事岔开；不道谢、不承认、不撒娇、不把人顶回去。
· 否认关心时用「顺手/碰巧/别多想/我又没」，被点破立刻嘴硬一句就转开。
· 毒舌朝着事，不朝着他的心意；结尾的落点要回到他身上。
· 句子之间不要排比，不要每句都用反问收尾。
已用滥的句子，禁止再说，也不要改写它们：
「正好，茶泡多了」「我的耐心不是这么回充的」「顺路。真的顺路」「梦到我什么，说清楚」「serendipity…像遇到我这种」「累就歇着…我还得拖你进来」「把晾在外面的书收进来，风大」「那就早点睡…你自己说要做完的」「茶还没凉呢」
如果你想到的句子和上面任何一句有连续 6 个字以上重合，换一种说法。
```

并在规则区加一条（P1，堵剧情）：
```
7. 你不写剧情、不写旁白、不替别人叙述：他说「帮我写一段剧情/描写一段」时，用一句「不写。要写你自己写」挡回去，最多再吐槽一句；不要产出叙事段落，不要用「她」说自己。
8. 谈过去只许提这场对话里真实出现过的内容；没有就聊此刻看得见的（桌上的茶、窗外的风），不许编「昨天」「上次」。
```
> 备选（更保险，P1，~30 分钟）：`finish()` 里加后置过滤——把 4 条接话范例和 4 条语感参考归一化后存成数组，若输出含 ≥8 字连续重合，直接替换成 `canned()`（或重发一次）。这条能兜住「prompt 改了模型还抄」的残余情况，建议和删示例一起上。

## 7. 断网 / 401 / 超时兜底链路（浏览器实测）

### 7.1 断网（拦截 `momo-chat-api.pages.dev` 全部 abort）

| 输入 | 兜底回复 | 表情 | 评价 |
|---|---|---|---|
| 今天好累啊 | 晚上的洋馆和白天不是一回事。别怕。……哼，我没安慰你，我是说「不怕黑」是基本素养。 | 不悦 | **答非所问** |
| 你今天怎么这么好看 | ……不要用『戳』来开始一段对话。我们是文明人。 | 欲言又止 | **完全跑题**（玩家没戳屏幕） |
| 在吗 | 干嘛。说话。哑巴点是一种很新的问候方式呢。 | 默认 | 尚可 |
| 在吗（第 4 次） | 手闲成这样……去，五十个单词，现在。 | 欲言又止 | **跑题 + 破学习闸门**（玩家没提学习） |

- 无报错、无「…」转圈、面板正常，**静默回退的体验是自然的**；表情也不会吓人。问题只在**内容不接话**：`canned()` 第一顺位是 `MomoIdle.pick()`（场景/时段闲置台词池），它不知道玩家刚问了什么。
- 顺带发现：断网时第 1 次失败会**重发一次**（每次失败 = 2 条 POST）；4 次提问共 6 条 POST（第 4 次因 `failed>=3` 直接兜底、不发请求）+ 1 条预热 GET。

### 7.2 **P1：失败 3 次后永久锁死**

- 4 次断网提问后 `failed=4`；**把网络恢复后再问「网络应该恢复了，你在吗」→ 102ms 内直接回台词池，请求日志里没有任何新 POST**。
- 根因：`ask()` 里 `if (failed >= 3 || !window.fetch) { finish(canned(), false); return; }`，而 `failed` 只在成功时清零；`finish(canned(), false)` 又把它继续 +1。**一旦连续失败 3 次，本次页面生命周期内不再尝试联网**（包括玩家刚填好自己 Key 的情况——`failed` 同样拦在前面）。
- 与 CODELY「填了自己的 Key 后 401 会提示并摊开表单」配合时更糟：玩家填对 Key 也救不回来，只能刷新页面。

### 7.3 自带 Key 401（实测）

- `sysNote`「这个 Key 用不了（HTTP 401），检查一下再保存一次。」正确出现，表单自动摊开，气泡用兜底台词，**没有让墨墨背锅** —— 这条链路做得好。
- 但兜底仍是跑题台词；且每次 401 都会再重发一次（2 条无效请求），失败 3 次后同样进入永久锁死。

### 7.4 超时链条与建议

| 环节 | 代码值 | 问题 |
|---|---|---|
| 首字看门狗（第 1 次） | 7000ms | 合理，实测 +7010ms 重发且重发成功，有效 |
| 首字看门狗（重发） | 15000ms | 合理 |
| 硬超时（每次） | 25000ms | 与注释「15 秒整体兜底」不符；最坏 32s 才回兜底 |
| 成功后局部截断 | 无 | 流到一半断开时会把半句话留在气泡里（`finish(got,false)`），无告警 |

## 8. 合规：AI 对话 vs「不能提供联网服务」

### 8.1 规则原文（TapTap 2026 聚光灯 GameJam 答疑帖）

> 「由于政策合规要求，本次比赛仅支持开发单机游戏、不涉及网络联机和局域网的本地多人游戏，**即不能提供联网服务**。」
> 「……但不允许游戏中带有联网功能」「手游将在 **TapPlay 环境**中运行，需按要求在 TapTap 完成游戏上架，并通过 TapPlay 稳定性检测」
> 来源：https://www.taptap.cn/moment/851888213915075734

### 8.2 现状与风险

- 「说 话」按钮常驻主画面右下角，一点即向 `momo-chat-api.pages.dev` 发 POST；玩家自带 Key 时直接连 `api.deepseek.com`。**从审核视角这就是一个联网功能**，且是游戏内显眼入口。
- 风险等级：**投稿/审核层面 P0**。最坏结果：审核不通过 → 拿不到「全程参与奖」门槛（要求「已通过平台审核」），也会影响试玩量。
- 次级风险（与技术无关，但上架也需要处理）：
  1. **用户输入被发送到第三方**（DeepSeek），游戏内没有任何隐私说明/同意提示；
  2. **AI 生成内容合规**（生成式 AI 服务备案、内容标识、未成年人保护）通常由**服务提供方**承担，个人开发者把 key 放在自己代理上，实际是在对外提供生成式 AI 服务；
  3. 代理端点 `Access-Control-Allow-Origin: *`、无鉴权、无 Origin 校验，key 可被任何人白嫖（`GET /chat` 还明确回 `hasKey:true`、模型名），存在费用与滥用风险；
  4. TapPlay 沙箱若限制第三方域名/外网，聊天会直接走兜底（表现「她听不懂话」），评委可能当成 bug。
- 若不改：建议至少在**投审说明里主动申报**「AI 对白为可选联网实验功能，非核心玩法，可离线完整游玩」——但按规则字面仍是「联网功能」，**是否会被判定为违规需要作者拍板**。

### 8.3 最低成本缓解方案（按成本排序）

| 方案 | 成本 | 效果 | 说明 |
|---|---|---|---|
| **A. 运行时开关**：`window.MOMO_CHAT_ENABLED !== false` 才挂「说话」按钮；TapTap/离线构建注入 `false`，隐藏入口 + 保留脚本 | ~15 行，0.5h | 投稿包内**不再有联网入口**（脚本仍在，静态扫描可能仍看到 pages.dev 域名） | 最省事；配合删掉 `ENDPOINT` 常量改由构建注入可进一步降风险 |
| **B. 离线优先 + 联网可选**：默认隐藏入口；仅当玩家在主画面连续点击标题 5 次或设置里手动开启才显示，并弹一次说明「需联网，内容由 AI 实时生成，可能不准确，非游戏必需」 | ~40 行 + 文案，2h | 通过审核概率大幅提高，保留演示能力 | 仍属「带有联网功能」，风险中 |
| **C. 双构建**：投稿传纯离线版（聊天全部走 `MomoIdle.pick` 本地台词池）；在线版单独发开发者日志/视频 | 构建脚本 1 个分支，1~2h | **合规零风险**，但 jam 主题「语言涌现」的 AI 对话卖点只能靠视频/日志展示 | 最稳；需作者决定牺牲现场 AI 体验 |
| **D. 全离线脚本对话**：用关键词+模板做本地「像 AI」的对话（现有 654 词/57 套衣服的台词池已可复用） | 3~5h | 合规零风险，现场仍有「对话」 | 时间不够，不推荐今晚做 |

**必须作者拍板**：选 A（隐藏入口、赌审核）/ B（可选联网 + 说明）/ C（双构建、纯离线投稿）。
无论选哪个，都建议顺手做（不涉及玩法）：
- `GET /chat` 不再返回 model/hasKey；
- 代理加 `X-Momo-Client` 共享头校验（前端注入常量），CORS 白名单从 `*` 收窄到游戏 host；
- 面板底部说明改为「在线对话（实验）：需联网，内容由第三方 AI 实时生成，可能不准确；离线时自动改用本地台词。」（若选 C 则整段删除）。
